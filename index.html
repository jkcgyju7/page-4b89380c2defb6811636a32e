客户端选择

先选加速器，再谈节点与套餐

365VPN 的订阅需要交给兼容 Clash、Surge 或其他常见订阅格式的客户端。选错客户端，常见后果是无法更新订阅、只能代理浏览器、或与系统 VPN 开关冲突。建议只同时运行一个客户端，避免规则互相覆盖。

按系统缩小范围

  • iPhone / iPad：优先考虑支持订阅与分流的 iOS 客户端，从商店安装后用 URL 导入。
  • Android：选择仍在维护的 Meta 内核图形客户端，注意授权 VPN 与自启动权限。
  • Windows / macOS：使用带系统代理或 TUN 模式的桌面端，便于覆盖终端与开发工具。
  • 路由器：仅在固件已支持订阅与规则时再导入，避免把家庭网关配成不可用状态。

选择时盯住四件事

能否从链接更新订阅；能否按域名分流国内直连；能否在失败时快速切换；配置文件是否便于备份。本站不托管安装包，也不提供来路不明的破解版下载。

导入前的检查清单

打开客户端前先核对：系统时间准确、网络能访问订阅地址、没有第二个系统 VPN 占用通道。导入成功后先用规则模式访问普通网页，再按需打开全局。

使用场景

365VPN 适合放进哪些工作流

把 365VPN 当成「需要跨境时再打开」的加速层，而不是全天候全局代理。下面几类需求最常见：查阅海外公开文档与代码仓库、观看套餐能力范围内的流媒体、参加跨境会议、以及希望游戏或即时通讯走更干净的线路。

家庭或多设备协作时，用同一订阅分别导入各端，在客户端里为视频、下载和国内银行网站写清直连规则，比把所有流量塞进一条通道更稳妥。

场景对照

资料与开发 — 终端、包管理器和 IDE 走代理，国内镜像保持直连。

影音浏览 — 仅对目标站点启用代理，减少无关流量消耗。

会议协作 — 开会前先测延迟，准备好备用节点，不要在会议中频繁切换内核。

游戏与实时通讯 — 需要客户端支持 UDP 与独立规则；具体线路能力以套餐页说明为准。

操作说明

从开通到连上的四步

365VPN 的配置可以概括成「开通 — 复制订阅 — 导入客户端 — 选择模式」。任何一步卡住，优先回到客户端日志，而不是反复重装。

  1. 选定套餐并开通。按流量与同时在线设备数决策，具体额度只以套餐模块显示为准。
  2. 保存订阅地址。当作密钥对待，不要发到群聊或截图外传。
  3. 在已安装的客户端中选择从 URL 导入或添加订阅，等待节点列表刷新。
  4. 使用规则模式完成一次访问测试，异常时更换节点、检查 DNS 与系统时间，再考虑切换全局或 TUN。

常见问题

365VPN 是机场订阅还是浏览器插件？

365VPN 以机场订阅形式工作，把节点和规则交给系统级客户端处理，可以覆盖应用与终端，而不是只加速某一个浏览器窗口。

第一次使用应该选哪款客户端？

以操作系统为准：iOS 选支持订阅导入的商店客户端；Android 选仍在维护的图形内核；桌面系统选带系统代理或 TUN 的客户端。先保证能更新订阅，再配置分流。

订阅链接泄露后要怎么处理？

立刻在账户侧重置订阅，使旧链接失效，然后在各设备客户端里替换新地址。不要把订阅当作可以公开的下载地址分享。

为什么连上了部分网站仍然打不开？

依次检查：是否真的启用了系统代理或 TUN、DNS 是否异常、规则是否把目标站点漏到直连、节点是否失效。先换节点并查看客户端日志，再决定是否改模式。

一台设备可以同时开多个加速器吗？

不建议。多个内核会抢系统 VPN 接口和端口，表现为能开不能上网。一设备保留一个客户端即可，多设备数量仍受套餐在线上限约束。

流量统计以客户端为准还是以套餐为准？

以服务端套餐统计为准。客户端本地计数常因握手、UDP 和重试用而有偏差，不适合用来对账。
